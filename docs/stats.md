# mmcheck stats: シナリオの複雑度の指標

```sh
bin/mmcheck stats scenario.yaml                # 人間向けの表示
bin/mmcheck stats --format json scenario.yaml  # 機械向け
bin/mmcheck stats --format agent --require 'score>=50' --require 'axis.branching>=60' scenario.yaml
                                               # 条件を満たすか(自動生成のループ向け。下の「条件」)
```

シナリオの「複雑さ」を、**複雑度のスコア**(0〜100 の1つの数)と、その元になる **軸ごとの指標** で出す。あわせて **水増しの候補** と、`mmcheck check` の error / warning の件数も出す。指標は検出結果ではない報告なので、仕様(`docs/spec.md`)と Lean の形式モデルの対象外で、Go 側だけの機能である。ただし、終了状態・居場所の区間・入手可能(§2.5)・実効制約とパターン(§4.7)は判定器と同じ関数で計算する。

R 群(構造・参照整合)の違反があると計算できない(終了コード 1)。入力エラーは終了コード 2。

## 複雑度のスコア `complexity`

下の指標を **0〜100 の1つの数** にまとめたもの。内訳(軸ごとのスコアと各項目の値)もあわせて出す。

0. 水増しの候補(下記)は数えない: 使われていない場所は場所の数から、何もしない往復の move はイベント数・移動回数・1人1時間あたりのイベントから、参照されない証言は証言の数から、何も明かさない手がかりはカードの枚数から、結末に関係しない選択の定義域の大きさの log₂ はパターン数の log₂ から除く。
1. 各項目を 0〜1 に写す。個数などの値 x は `x / (x + r)` で写す。r は **参照値** で、x = r のとき 0.5 になる。上限で切らないので、値が増えれば必ずスコアも増える。もともと 0〜1 の割合はそのまま使う。
2. 軸のスコアは、その軸の項目の平均。
3. 複雑度は、**当てはまる軸** の平均 × 100(重みは等しい)。探索フェイズ(`exploration`)がなければ探索の軸、パターンを数え上げられなければ分岐の軸を除く。

| 軸 | 項目(参照値 r) |
|---|---|
| 規模 | プレイヤー数(4)、場所の数(8)、イベント数(50) |
| タイムライン | 1人1時間あたりのイベント(3)、1人あたりの移動回数(6)、非公共の場所での遭遇(5) |
| 情報の流れ | 誰かが信じている偽の知識の数(2)、証言の数(10)、伝聞の最長の段数(2)、入手経路が1つ以下の真相の知識の割合 |
| 探索 | カードの枚数(12)、必要な最小枚数 ÷ 引ける枚数(揃わなければ 1)、無作為に引いて揃わない確率 |
| 分岐 | log₂(パターン数)(6)、結末のエントロピー(1.5 bit)、選択が結末を左右する割合のプレイヤー平均、対立するゴールの組の数(3) |

参照値は `examples/` の3本を見て「中くらい」と思える値に置いたもので、絶対的な基準ではない。**同じ版の式どうしで比べる** こと。項目・参照値・重みを変えたら `complexity.version`(`ComplexityVersion`)を上げる。

| | yaml-demo | araki-konomi | hexagon-house |
|---|---|---|---|
| 複雑度(v1) | 31.5 | 37.7 | 49.8 |
| 規模 / タイムライン / 情報 | 26.3 / 28.9 / 27.3 | 43.6 / 39.7 / 38.2 | 56.4 / 56.4 / 46.7 |
| 探索 / 分岐 | — / 43.3 | 22.2 / 44.7 | 22.2 / 67.3 |
| 水増しの候補 | なし | 往復 `tom_03`/`tom_04`、知識 `f_k_felt_gaze` | 場所 `port`、往復 `ushirokawada_05`/`06` |

## 水増しの候補 `padding`

複雑度のスコアを上げるが、シナリオの中で何の役にも立っていない要素。自動生成のループが中身ではなく数字を稼ぐのを防ぐために数え、複雑度からは除く。原作を忠実に写したシナリオでも少し出る(上の表)ので、**候補** であって誤りではない。

| 指標 | 定義 |
|---|---|
| `unused_locations` | 誰も居たことがなく(往復の move で居ただけの場所も含む)、どのイベント・アイテム・手がかり・盤面・断言・ハンドアウトにも現れない場所 |
| `idle_moves` | 行って何もせずに元の場所へ戻る往復の、行きと帰りの move。行きが致命的でない徒歩で、requires がなく、証言の対象でなく、滞在中にそのキャラクターが参加者・観察の対象になるイベントも、そのキャラクターについての断言もなく、非公共の場所でほかの誰とも居合わせていないもの。自室に戻って一晩過ごすような、何も起きないがアリバイとして意味のある滞在は往復ではないので含めない |
| `unused_facts` | プレイヤーが手に入れられず(§2.5)、真相・requires・ゴール・否定の関係・論理式の `truth`・ハンドアウトのどこからも参照されない知識 |
| `empty_clues` | 何も明かさず、アイテムにも結び付かない手がかり |
| `irrelevant_choices` | ほかの選択の値を固定したとき、この選択のどの値でも、実現できる(結末, ゴールの達成)の組の集合が同じになる選択 |
| `total` | 上の件数の合計 |

**捕まえないもの**: 表面上は使われている水増し。たとえばプレイヤーが知っているだけで誰も使わない真の証言や、互いに打ち消すだけのゴールの組。これらは複雑度に入る。

## 条件 `--require`

`--require '<条件>'` を何度でも指定でき、すべて満たせば終了コード 0、どれかを満たさなければ 1 になる。条件式の誤りと入力エラーは 2。R 群の違反があると指標を計算できないので 1。

```
条件   := 値 比較 数              比較: >= <= > < == !=
値     := パス | 集計(パス)       集計: min max sum avg count
パス   := JSON のキーを . でつないだもの(途中の配列は要素ごとに辿る)
別名   := score(複雑度)、axis.<size|timeline|knowledge|exploration|branching>(軸のスコア、0〜100)、
          check.errors / check.warnings(mmcheck check の件数)
```

- 値が複数になるパス(`branching.players.pivotal` など)は集計しないと満たさない。配列そのものは `count(...)` で数える。
- 対象外の軸(探索フェイズがないときの `axis.exploration` など)の条件は満たさない。
- `--format agent` は `{ok, complexity_version, failed, requirements: [{expr, ok, value, message}], stats}` を返す。`message` に、何がいくら足りないかが入る。

### 自動生成の合格条件の例

```sh
mmcheck stats --format agent \
  --require 'check.errors==0' --require 'check.warnings==0' \
  --require 'complexity.version==1' \
  --require 'padding.total==0' \
  --require 'score>=50' --require 'axis.branching>=60' \
  --require 'branching.entropy_bits>=1' \
  --require 'min(branching.players.pivotal)>0' \
  --require 'count(branching.goal_conflicts)>=2' \
  --require 'knowledge.min_solution_sources>=2' \
  scenario.yaml
```

- **`check` の合格を条件に含める。** 矛盾のあるシナリオの複雑度には意味がない。
- **`padding.total==0` を含める。** 水増しは複雑度に数えないが、残っていると読み手の負担になる。
- **軸の平均だけでなく、意味のある個別の項目でも縛る。** 平均だけだと、ほかの軸で穴埋めできる。
- **式の版を固定する。** 参照値や重みを変えると、同じしきい値の意味が変わる。
- しきい値は3本の例から決めた仮の値で、`axis.branching>=60` を満たすのは hexagon-house だけ。原作の araki-konomi(44.7)も落ちる。

## 指標

### 規模 `size`

プレイヤー・NPC・場所・アイテム・イベント・知識(うち偽)・証言(うち偽)・手がかり・断言・ゴール・選択・エンディングの数。

### タイムライン `timeline`

| 指標 | 意味 |
|---|---|
| `duration_minutes` | `end_time − start_time` |
| `moves` | move イベントの数 |
| `events_per_player_hour` | プレイヤーが参加者のイベントの延べ数 ÷ (プレイヤー数 × 時間)。プレイヤーが追う時系列の密度 |
| `encounters` | 非公共の場所で2人の居場所の区間(§2.3)が重なった回数。認知されているかは問わない(認知されていないものは T009) |
| `per_character` | キャラクターごとのイベント数・移動回数・訪れた場所の数 |

### 情報の流れ `knowledge`

| 指標 | 意味 |
|---|---|
| `max_relay_depth` | 伝聞の最長の段数。直接得た知識(初期知識・scene・observe・learn)を 0 とし、tell で伝わるたびに 1 足す。知識を最初に得たときの段数で数える |
| `solution[]` | 真相の知識(`solution_facts`)ごとの入手経路: 終了時に知っているプレイヤー `held_by` と、明かす手がかり `clues`。`sources` はその合計で、少ないほど見落としやすい。`relay_depth` は知っているプレイヤーのうち最も浅い伝聞の段数 |
| `min_solution_sources` | `sources` の最小値。1 なら、その1経路を逃すと真相に届かない知識がある |
| `lies[]` | 偽の知識ごとに、終了時に信じているプレイヤーと、否定する知識のうち入手可能なものの数 |
| `secrets` | ゴールの `conceals` に現れる知識の数 |

### 探索 `exploration`(手がかりか `exploration` があるとき)

| 指標 | 意味 |
|---|---|
| `cards` | 探索カード(`clues`)の枚数 |
| `draws` | 引ける合計 D = `draws_per_player × プレイヤー数` |
| `clue_only` | 手がかりからしか手に入らない真相の知識の数(K010 と同じ定義) |
| `min_cards` | それらをすべて明かすのに要る最小の枚数(揃わなければ −1) |
| `slack` | `draws − min_cards`。小さいほど、引くカードを外せない |
| `random_cover` | D 枚を **無作為に** 引いたときに、それらがすべて揃う確率(包除原理で正確に計算)。実際はプレイヤーが選んで引くので、「カードの名前から当たりを推測できないとき」の難しさの目安 |

### 分岐 `branching`

| 指標 | 意味 |
|---|---|
| `variables`, `assignments` | 変数(ゴール + 選択)の数と割り当ての総数 N。N が 2²⁰ を超えると数え上げない(`enumerated: false`) |
| `patterns` | パターン(実効制約を満たす割り当て)の数 \|P\| |
| `outcomes[]` | パターンごとの結末(当てはまるエンディング。複数なら `+` で連結、なければ空文字列)の分布 |
| `entropy_bits` | 結末の分布のエントロピー。パターンを等しく重み付けした **構造上** の値で、実際のプレイでの確率ではない。log₂(エンディング数) に近いほど結末が偏りなく分かれる |
| `players[].pivotal` | ほかのプレイヤーの選択の値の組(パターンに現れるもの)のうち、このプレイヤーが自分の選択を変えると結末が変わりうるものの割合。選択を持つプレイヤーだけ |
| `goal_conflicts` | owner の違うゴールの組で、どちらもいずれかのパターンで達成できるが、同時に達成できるパターンがないもの。プレイヤー間の対立の構造 |

## 扱わないもの

- **推理の深さ**: 仕様には「知識 A と B から C が分かる」という推論の関係がないので、真相までに何段の推論が要るかは測れない。`solution[].sources` は「入手できる経路の数」であって、推理の難しさではない。
- ミスリードの巧妙さ、物語の盛り上がり、プレイヤー間の駆け引きの強さ。
