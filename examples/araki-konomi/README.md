# サンプル: 荒木コノミの真相

`riddory/docs/stories/araki-konomi-no-shinsou` のハンドアウト・エンディング・真相・カード(ルームデータ内 23 枚)を、**仕様 0.2.0** の正規化 JSON で表したもの。

- `scenario.json`: モデル化したシナリオ(イベント 30 件)
- `expected.json`: 仕様 0.2.0 の試作判定器(Python、使い捨て)による出力。**検出結果は 0 件**

## モデル化の方針

「解説/真相」の時系列(コノミは1人で練習し、視線から逃げて屋上へ行き、18:00 に落下)を**客観的なタイムライン**とした。各ハンドアウトの記述は、その人物の**知識**(`knows`)として載せている。

| 原作 | 仕様 0.2.0 での表現 |
|---|---|
| 16:00〜18:30(半年前の事件当日) | `start_time` = 960、`end_time` = 1110 |
| PC 3人 + 故人コノミ | `characters`。コノミは `npc: true` |
| 空き教室、図書室、部室、廊下、自販機、屋上、落下地点 | 校舎・屋上・屋外の3エリア。移動時間は**推定** |
| ソウスケの「付き合っていた」「一緒に練習した」 | ソウスケの知識(`initial_knowledge` / `observe`)。**誤った認識であることは表現できない** |
| ソウスケが隠れてコノミを見ていた(真相) | `observe`(`targets: [konomi]`)。コノミには気づかれていない |
| コノミの落下 | 屋上 → 落下地点への 0 分の `travel` + `die` |
| 証拠カード・心の声・事前情報 | 知識と `clues` |
| 犯人投票 | 3人それぞれの投票を列挙型の選択にした(tsumugi / sousuke / tom / other) |
| 目標「死の原因となった人を特定」 | ゴール ⇔ 自分の投票が sousuke |
| エンディング1〜4(最多得票者 / その他または同数) | 「3票中2票以上」を論理式で書いた |

## 判定結果

**検出結果は 0 件。** G 群(投票 4³ = 64 通り × ゴール)では、エンディングがどのパターンでもちょうど1つに決まることを確認できた。

ただし、このシナリオの核心である次の2点は、**0.2.0 では検査の対象にならない**。
- 信頼できない語り手(ソウスケの思い込み)
- 真相にある「18:00 には全員アリバイがある」

## モデル化の途中で(手作業で)見つけた不整合の候補

| # | 内容 |
|---|---|
| 1 | **トムの時刻のずれ**: 証拠カードは「**18:00** に悲鳴を聞き窓の下を見るとコノミ氏の死体があった」。ハンドアウトの時系列表は「**18:10** 部室にて女性の悲鳴を聞き…」。ツムギの発見(悲鳴)は 18:00 なので、時系列表の 18:10 が誤りと思われる |
| 2 | **ソウスケの出発時刻とアリバイ**: 証拠カードは「**18:00** に…一階に向かう」。時系列表では 17:50 の行にまとめて書かれている。真相は「18:00 には全員アリバイがある」だが、18:00 に屋上を出たのなら、落下の瞬間にちょうど屋上を出たことになり、アリバイが際どい。カードを 17:55 などにすると明確になる |

どちらも、0.2.0 の判定器では検出できない(下記 M1, M2)。

## 見えた仕様の不足(0.3.0 の候補)

| # | 不足 | 改善案 |
|---|---|---|
| K1 | **誤った認識・嘘を表せない。** ソウスケの「付き合っていた」は誤りだが、0.2.0 では知識と区別できない。このシナリオの核心 | `facts[].truth: false` と `contradicted_by: [facts]` を追加する。誤った知識を持つ人物がいる場合、それを否定する正しい知識がゲーム中に手に入ること(手がかりかハンドアウト)を検査する |
| K2 | **真相の主張(アリバイ)を検証できない。** 「18:00 に屋上にはコノミしかいない」「01:00 にカイチョウは自室にいない」など | `assertions` を追加する: `{"absent"/"present": {location, at, characters}}`。居場所の区間に照らして error を出す。真相の解説が成り立っていることを機械的に保証できる(六角館にも効く) |
| K3 | **別の場所からの知覚を表せない。** 窓から下を見る、悲鳴を聞く、教室の前を通りかかる | `perception: [{from, to}]`(見える・聞こえる場所の組)を追加し、observe の target がこの組でつながった場所にいてもよいことにする |
| K4 | **証言の時刻と、実際の時刻を比べられない。** 知識が中身のない ID なので、カードの「18:00」と時系列表の「18:10」を突き合わせられない | 知識に `about: event` と `claimed_at: Time` を持たせ、主張した時刻と対象のイベントの時刻がずれていたら検出する。時系列表の各行も、同じ形の主張として書けるようにする |
| K5 | **徒歩ではない移動(落下、運搬)を表せない。** 0 分の travel で代用したが、そうすると誰でも屋上から 0 分で降りられてしまう | move に `mode: "fall"` などを追加し、移動時間の検査を省略する(経路の存在だけを見る) |
| K6 | **同じ分に「落下して即死」を置けない** | die を直前のイベントと同じ分に置けるようにする(T005 の例外)か、move に `fatal: true` を持たせる |
| K7 | **探索カードの山札が場所ではない**(「コノミについて」など) | clue に `deck` を追加し、`location` / `item` / `deck` のどれか1つを必須にする |
| K8 | **投票結果のエンディング条件が冗長。** 「3票中2票以上」を全組み合わせで書いた | 論理式に `{"plurality": {"votes": [...], "value": v}}` と `{"tie": {...}}` を追加する(数え上げで評価できる) |
