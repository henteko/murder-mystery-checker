# サンプル: オタサーの姫殺人事件〜六角館の殺人編〜

`the-hexagon-house-murders` のハンドアウト・エンディング・真相・カード(ルームデータ内の画像 28 枚)を、**仕様 0.2.0** の正規化 JSON で表したもの。

- `scenario.json`: モデル化したシナリオ(イベント 85 件、場所 11 か所)
- `expected.json`: 仕様 0.2.0 の**試作判定器**(Python、検証用の使い捨て)による出力。Lean オラクルの出力ではないので、Phase 3 でオラクルの出力に置き換える。

**原作に忠実にモデル化している。** 記述のない行為は補っていない。例外は次の2点で、どちらも `note` に明記している。
- 移動時間は推定値
- 腕時計を自室の鞄に入れる行為(鞄から盗まれたという記述から推定)

## 判定結果(試作判定器)

**error 4件、warning 2件。** どれも原作の2つの不整合から出ている。

| 不整合 | 検出結果 |
|---|---|
| **リップクリーム**: ウシロカワダは「明日返そうとポケットにしまった」のに、探索カードでは「ウシロカワダの部屋」で見つかる | H006 error(盤面の宣言と終了状態が違う)、K005 error(手がかりのアイテムが宣言した場所にない)、H003 warning(ハンドアウトの所持品に記載がない) |
| **睡眠薬**: シメジは睡眠薬を持ったままで、部屋に置く記述がないのに、探索カードでは「シメジの部屋」で見つかる | 同上(H006、K005、H003) |

0.1.0 で出ていた G008(ヒメにゴールがない)は、`npc` を導入したので出なくなった。

**修正の確認**: 「シメジが 0:02 に睡眠薬を自室に置く」「ウシロカワダが 01:14 にリップクリームを自室に置く」の2イベントを加えると、検出結果は **0件** になる(F1)。

## 気づいた点(0.3.0 以降の候補)

- 1つの不整合から H006、K005、H003 の3件が出る。どれも正しい指摘だが重複が多い。表示層(Go の text 出力)で関連する検出結果をまとめて表示するのがよさそう(仕様の出力は今のまま)。
- 死亡した人物が scene に入ると、T010 に加えて T007 も出る。遺体の位置は正しく扱えているので、これも許容範囲とした。
- 投票の連動(「ストーカーを特定」⇔ 投票先)を `constraints` で手書きしている。ゴールに `condition` を直接書けると、より自然に書ける。
