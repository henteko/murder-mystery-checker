# サンプル: オタサーの姫殺人事件〜六角館の殺人編〜

`the-hexagon-house-murders` のハンドアウト・エンディング・真相・カード(ルームデータ内の画像 28 枚)を、仕様 0.1.0 の正規化 JSON で表したもの。

- `scenario.json`: モデル化したシナリオ(イベント 93 件、場所 11 か所)
- `expected.json`: 仕様 0.1.0 の**試作判定器**(Python、検証用の使い捨て)による出力。Lean オラクルの出力ではないので、Phase 3 でオラクルの出力に置き換える。

## 対応表

| 原作 | 仕様での表現 |
|---|---|
| 8/10 17:00 〜 8/11 08:20 | `start_time` = 1020、`end_time` = 1940(8/10 0:00 を 0 とした分) |
| PC4人 + NPC ヒメ | `characters` 5人。ヒメにはゴールもハンドアウトもない |
| 孤島の港、神社、喫煙所、館内(各自室、食堂、大広間、廊下) | `locations` 11か所 |

| 各ハンドアウトの「時系列」と本文 | `events`(移動 move / 同席 scene / 受け渡し transfer / 拾う pickup / 置く drop / 使う use / 知る learn) |

制約の内容:
- 「カイチョウが最多にならない」(カイチョウ、クロセの目標)⇔ ¬`c_vote_kaichou_most`
- 「犯人を最多にする」(シメジ、ウシロカワダの目標)⇔ `c_vote_kaichou_most`
- クロセの「カイチョウの私物を2つ」と、シメジの「血の付いたアイテム + ヒメの私物2つ」は、どちらも万年筆を必要とするため同時には達成できない

## 判定結果(試作判定器)

error はない。

| コード | 内容 | 評価 |
|---|---|---|
| G008 (warning) | `hime` にゴールがない | NPC を表す方法が仕様にないために出る誤検知(提案 E) |
| **H003 (warning)** | ウシロカワダはタイムライン終了時にリップクリームを**所持**しているが、ハンドアウトに記載がない | **原作の不整合の候補。** ハンドアウトでは「明日返そうとポケットにしまった」とあるが、リップクリームは探索カード「**ウシロカワダの部屋**」で見つかる。部屋に置く行動が書かれていない |

補足: 睡眠薬も探索カード「シメジの部屋」で見つかるが、シメジのハンドアウトには部屋に置く記述がない。このサンプルでは「0:02 に自室に置く」イベントを補っている(`note` に明記)。

## モデル化して見えた仕様の不足と改善案

| # | 不足 | 影響 | 改善案 |
|---|---|---|---|
| A | 移動時間を全ての組で書く必要がある(11か所で110エントリ) | 書くのが現実的でない | 場所を**エリア**(館内など)にまとめ、エリア内とエリア間の既定移動時間を書けるようにする。正規化 JSON は平坦なままにし、YAML の変換で展開する |
| B | 同じ場所に同時にいるのに、どちらもそれを把握していない状況を検出できない(M4) | 「その時間その部屋には誰もいなかった」という証言の矛盾は、マダミスで最も多い矛盾の一つ | 規則を追加: 居場所の区間が重なる2人がいて、その区間に両者を含む scene がない場合に warning。廊下や大広間のような共用の場所は対象外にできるようにする |
| C | `learn` に場所の条件がない(「神社で目撃した」を神社にいなくても learn できる) | 目撃証言の正しさを検査できない | `observe {character, location, facts}`: その場所にいることを事前条件にする |
| D | scene に参加者が知識を得る効果がない(同時刻に learn を書くと T005 になるため、1分ずらす必要がある) | 書きにくく、不自然 | scene に `reveals: [facts]` を追加し、効果として参加者全員の knows に加える |
| E | NPC や被害者を表せない(ヒメに G008 が出る。死後にも行動できてしまう) | 誤検知と、矛盾の見逃し | `characters[].npc: true` で G008 の対象から外す。`die` イベントを追加し、死亡後に参加者になれない規則(T009)を設ける |
| F | ゲーム開始時の**場所の中身**(探索カード)を宣言できない | リップクリームの不整合が warning(H003)にしかならない | `board: [{location, items}]` を追加し、終了状態と照合する(error) |
| G | 手がかりがアイテムに付いている場合(置き時計 → 01:00)を表せない | 手がかりの場所とアイテムの場所がずれても気づけない | clue に `item` を指定できるようにし、その場所はアイテムのゲーム開始時の場所とする |
| H | 所持品に関する目標(万年筆の取り合い)の排他性を手で制約に書く必要がある | 書き漏れると G 群の検査が甘くなる | 将来: ゴールの条件に「ゲーム終了時に所持している items」を書けるようにし、アイテムの所持者は1人であることから排他制約を自動で導く |
| I | 投票のような多値の結果を真偽値で表すしかない | 「同票」の扱いを自分で決めて符号化する必要がある | 選択に値の範囲(列挙型)を持たせる。真偽値に展開すれば今の G の意味論に帰着できる |
| J | 知識は中身のない ID なので、「0:50〜1:07 の間2人は喫煙所にいた → 01:00 のアリバイ」のような推論は検査できない | 推理の妥当性そのものは対象外 | 対象外のままにする(将来の課題) |
